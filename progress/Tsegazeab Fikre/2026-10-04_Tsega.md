## ✅ What I Did Today

- Discovered an **IDOR (Insecure Direct Object Reference)** vulnerability in the **vehicle report** functionality, where a user could access **other users' vehicle reports**.

## 📚 What I Learned

- **NoSQL Injection:** Learned how applications using NoSQL databases (such as MongoDB) can be vulnerable when user input is passed directly into queries without proper validation or sanitization, allowing attackers to alter query logic.
- **Input Validation & Sanitization:** Reinforced how important it is for applications to validate and sanitize all user-supplied input before using it in database queries.
- **IDOR / Broken Access Control:** Learned how applications can expose other users' resources when API endpoints fail to verify whether the authenticated user is authorized to access the requested object.
- **Sensitive Data Exposure:** Understood how an IDOR can lead to leakage of personally identifiable information (PII) such as email addresses, and internal identifiers such as vehicle IDs.
- **API Security:** Improved my understanding of how vulnerabilities can exist directly within API endpoints even when the web application's normal functionality appears to enforce access controls.
- **Vulnerability Verification:** Learned the importance of confirming the actual security impact of a suspected vulnerability rather than stopping after identifying an unusual response.
- **Practical Pentesting:** Improved my ability to move from discovering an endpoint to testing how its parameters affect authorization, query logic, and data access.
