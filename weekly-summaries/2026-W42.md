### Tsegazeab Fikre — 2026-10-13


**Roadmap Track:** Web Security

## ✅ What I Did Today

- Continued working through **PortSwigger Web Security Academy** labs, focusing on authentication vulnerabilities.
- Studied and practiced **multi-factor authentication (MFA / 2FA) bypass techniques**, including:
  - Bypassing 2FA by skipping the verification step entirely
  - Exploiting **flawed 2FA verification logic** where the account identifier is client-controlled
  - **Brute-forcing 2FA verification codes** using Burp Suite and Turbo Intruder
- Set up **Burp Suite Professional** on Kali Linux (Java 21, license activation, desktop shortcut, shell alias).
- Learned how to use **Burp Macros** in combination with **Intruder** to automate multi-step login flows.
- Practiced **brute-forcing a stay-logged-in cookie** by reverse-engineering the cookie format (`Base64(username:MD5(password))`) and forging cookies for other users.
- Studied **password reset vulnerabilities**, including:
  - **Password reset poisoning** via the `Host` and `X-Forwarded-Host` headers
  - Successfully captured a victim's reset token through Burp Collaborator and used it to reset another user's password
- Explored **password change functionality flaws**, including client-controlled usernames and message-based brute-force oracles.
- Began studying **XML External Entity (XXE) injection**, covering how XXE works, what it can achieve, and how to exploit it to retrieve files from a server.

## 📚 What I Learned

- **2FA Bypass Techniques:** Learned that 2FA is only as strong as its implementation — a skipped verification step, a tamperable cookie, or a brute-forceable code can all defeat it.
- **Burp Macros + Intruder:** Understood how to chain multiple requests (login → 2FA page → code submission) into a macro so that each Intruder request carries a fresh, valid session.
- **Rate Limiting Bypass:** Learned that sending multiple credentials in a single request (e.g., a JSON array of passwords) can bypass rate limiting entirely.
- **Cookie Forgery:** Learned how predictable "remember me" cookies built from usernames and password hashes can be reverse-engineered and brute-forced.
- **Password Reset Poisoning:** Understood how manipulating host-related headers can redirect reset tokens to an attacker-controlled server.
- **Password Change Logic Flaws:** Learned how hidden form fields, missing current-password checks, and inconsistent error messages can enable account takeover and user enumeration.
- **XXE Fundamentals:** Learned how XML external entities can be abused to read files, perform SSRF, and escalate to full server compromise.
- **Burp Suite Proficiency:** Improved my ability to use Repeater, Intruder, Macros, Resource Pools, Grep Match rules, Session Handling Rules, and Burp Collaborator.

## 🚧 Blockers

- Some labs required repeated attacks because tokens or codes reset mid-attack, making it difficult to know whether the exploit logic or the timing was the issue.
- Understanding the exact order of operations in Burp's Session Handling Rules (macro execution vs. cookie jar updates) took additional experimentation.
- Balancing deep study of each vulnerability class with the goal of making steady progress through the Academy.
